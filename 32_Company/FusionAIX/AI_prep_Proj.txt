


1. Agentic AI

In my recent project, I built an AI-powered vehicle assistant system using a multi-agent architecture with LangGraph. The idea was to handle different types of user requests in a smart and efficient way, even when there are challenges like limited hardware or no internet connectivity. I designed an orchestrator agent that acts like the brain of the system — it understands the user query and routes it to the right agent. For example, a local agent runs on a lightweight model (Phi 3.5 via Ollama) and handles offline queries using a RAG setup with vector databases like ChromaDB and LanceDB. A cloud agent uses a more powerful model (like GPT-4o) to fetch real-time information such as weather, navigation, or nearby places. I also built a CAN agent that directly communicates with the vehicle using the Kvaser CAN library, enabling actions like checking fuel status or controlling vehicle functions.


To make the system more interactive, I added voice input using OpenAI Whisper for speech-to-text and implemented hotword detection using Azure Speech SDK so the assistant can be triggered naturally. I also integrated tool calling using an MCP server (FastMCP) to allow agents to perform real-world actions like sending CAN messages or calling external APIs. Additionally, I handled network limitations by introducing a Celery queue system — if the internet is unavailable, requests are queued and processed once connectivity is restored. Overall, the system was deployed on an edge NVIDIA device, making it efficient, responsive, and capable of working in real-world driving conditions.

2. Phi3.5 Vision Instruc Model

In another project, I worked on fine-tuning a vision-language model, specifically the Phi 3.5 Vision Instruct model, for detecting anomalies from vehicle front camera images. The main challenge was to build an accurate model while working under hardware constraints, as full-scale fine-tuning typically requires very high GPU memory. To solve this, I used parameter-efficient techniques like LoRA and QLoRA, which allowed me to fine-tune the model on a 40GB NVIDIA A100 GPU instead of needing much larger resources. I followed a teacher-student approach, where a stronger model like GPT-4o was used to generate high-quality annotations such as image descriptions, classifications, and severity levels, which were then used to train the smaller model.

For the training pipeline, I used Hugging Face Transformers, PyTorch, and custom data collators to handle the multimodal dataset. The dataset included fields like image path, description, classification, and severity. I handled preprocessing, batching (with batch size of 1 due to memory limits), and hyperparameter tuning during training. After training, I evaluated the model using metrics like BLEU, ROUGE, and BERTScore to ensure good performance on both understanding and generation tasks. This project helped me build an efficient, domain-specific model that can run on edge systems and assist in real-time vehicle safety use cases.

3. Yolo v11

I also worked on fine-tuning a YOLO v11 model for object detection in vehicle-related scenarios. The goal was to accurately detect and identify important objects from camera input, such as obstacles, pedestrians, or road-related elements. I used a custom dataset specific to the use case and performed data preprocessing and annotation to ensure good quality training data. Then, I fine-tuned the YOLO v11 model by adjusting hyperparameters like learning rate, batch size, and number of epochs to improve detection accuracy for our domain.

After training, I deployed the model using Flask and Docker, making it easy to run as an API service. This allowed the system to take image input and return detected objects in real time, which can be integrated with other systems like the ADAS assistant. The focus of this project was to build a fast and efficient object detection pipeline that works reliably in real-world conditions and can be easily deployed and scaled.
